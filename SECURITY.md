# Политика безопасности

## Поддерживаемые версии

Проект опубликован как `0.1.x`; исправления безопасности выходят только для
**последней** версии из `version.json` / `CHANGELOG.md`.

| Версия | Поддержка |
|---|---|
| последняя `0.1.x` | да |
| более старые | нет, обновитесь |

## Как сообщить об уязвимости

Пожалуйста, **не публикуйте детали эксплойта** в открытом виде до исправления.

1. Создайте Issue в GitHub с пометкой **[SECURITY]** в заголовке:
   `[SECURITY] Краткое описание`.
2. Укажите:
   - версию пульта (`version.json`);
   - модель и прошивку колонки;
   - шаги воспроизведения;
   - ожидаемое и фактическое поведение;
   - есть ли риск выполнения команд от root.
3. Если GitHub позволяет private security advisory — используйте его вместо
   публичного Issue.

Проект поддерживается одним автором, поэтому фиксированного срока ответа нет.
По возможности подтвержу получение и предложу план исправления. Публичное
раскрытие деталей — после выхода патча или по согласованию с автором.

## Модель безопасности

- Проект рассчитан на **уже рутованную** колонку и запускается от root.
  Скриптов получения root, подмены DNS, установки ключей eMudhra и подобных
  эксплойтов в репозитории **нет и не будет**.
- Панель работает по **HTTP** в локальной сети на порту `8055`.
  Публиковать порт в интернет нельзя.
- PIN опционален. При включении он проверяется на сервере: без куки отдаётся
  только страница входа, `/index.html` запрещён, CGI и `/state` отвечают 401.
  Запросы с localhost (сам пульт и демоны) проходят без PIN.
- Секреты (ключи LLM, VPN-подписка, Glagol-токен, PIN-хэш, чаты) хранятся в
  `/data/mypult` с правами `600` и не попадают в репозиторий.
- Резервная копия из панели **содержит секреты** — её нельзя прикладывать к
  Issue или коммитить.
- HTTPS не используется: самоподписанный сертификат даёт предупреждение, а
  Let's Encrypt требует публичный домен.

## В области действия

- обход PIN-гейта;
- выполнение команд/чтение файлов через CGI;
- утечка секретов из `/data/mypult`;
- CSRF/SSRF в CGI и прокси `/luna/`;
- ошибки авторизации в `/state` и `index.py`;
- повышение привилегий внутри уже запущенного пульта.

## Вне области действия

- получение root на колонке, прошивка, загрузчик;
- облачные сервисы Яндекса, Glagol, Luna, YAM и Entware;
- физический доступ к устройству;
- DoS в пределах собственной локальной сети;
- последствия включения VPN или установки сторонних пакетов.

## Safe harbor

Исследование безопасности на **своём** устройстве приветствуется.
Не атакуйте чужие колонки и не публикуйте данные других пользователей.
Автор не несёт ответственности за последствия экспериментов на устройстве.
