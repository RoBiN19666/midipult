# Публикация на GitHub

Проект подготовлен к публикации: личные данные, секреты, локальные логи и
скриншоты с реальными IP/SSID исключены через `.gitignore`.

## Что намеренно не попадает в репозиторий

| Путь | Почему |
|---|---|
| `.mypult-station` | IP вашей колонки |
| `.mypult-hash` | локальное состояние деплоя |
| `push.log` | журнал заливки с адресами |
| `tests/*.png`, `tests/shot-*.png` | скриншоты с IP, SSID и подпиской |
| `__pycache__/`, `*.pyc` | сборочный мусор |
| `/data/mypult/*` | токены, ключи LLM, VPN-подписка, DNS, PIN — **никогда** не коммитить |
| `auth.json`, `volume.json`, `ring.json` | создаются только на устройстве |

Секреты создаются на колонке в `/data/mypult` с правами `600` и в исходниках
отсутствуют. Резервная копия из панели тоже содержит ключи — её нельзя
прикладывать к issue или коммитить.

## Вариант A — через git (рекомендуется)

Установите [Git for Windows](https://git-scm.com/download/win), затем в папке проекта:

```powershell
git init
git add .
git status                 # просмотрите список: не должно быть секретов и IP
git commit -m "Initial commit: MidiPult"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```

Если `git status` показывает что-то лишнее — добавьте путь в `.gitignore`
и повторите `git add .`.

## Вариант B — через веб-интерфейс GitHub

1. Создайте пустой репозиторий (без README).
2. На странице репозитория: **Add file → Upload files**.
3. Перетащите папки `cgi-bin`, `deploy`, `docs`, `init.d`, `lighttpd`,
   `service`, `src`, `tests` и файлы:
   - `index.html`, `index.py`, `manifest.json`, `favicon.ico`,
     `icon-192.png`, `icon-512.png`, `icon.png`, `icon-circle.png`;
   - `README.md`, `FAQ.md`, `SECURITY.md`, `CHANGELOG.md`, `LICENSE`, `.gitignore`;
   - `version.json`.
4. Не загружайте `tests/*.png`, `.mypult-station`, `push.log`, `auth.json`,
   `llm.json`, `vpn.json` и прочие файлы из `/data/mypult`.

## Проверка перед публикацией

```powershell
# реальные адреса, токены LLM, подписки, PIN
Select-String -Path *.md,*.html,*.json,cgi-bin\*.py,service\*.py,deploy\* `
  -Pattern "192\.168\.(?!1\.100)|y0__|sk-[A-Za-z0-9]{10,}|vless://|vmess://|trojan://|Session_id|mypult_token="
```

Ожидаемый результат — пусто (кроме учебных примеров вида `192.168.1.100`).

Дополнительно проверьте, что не попали:

- `auth.json` (PIN-хэш и токен);
- `llm.json` (ключи провайдеров);
- `vpn.json` (подписка);
- `chats.json` (личные вопросы к нейросети);
- логи `voice.log`, `mypult.log`.

## Релиз и четыре файла

У каждого релиза должно быть **четыре** файла:

- `Source code (zip)` и `Source code (tar.gz)` — GitHub добавляет сам;
- `midipult-<version>.tar.gz` — архив панели для обновления из веб-интерфейса;
- `midipult-<version>.tar.gz.sha256` — контрольная сумма архива.

Если архива и SHA нет, панель показывает «В релизе панели нет архива
обновления» и self-update не работает (именно так было у `v0.5.63` и
`v0.5.64` — файлы восстановлены вручную).

Порядок выпуска:

1. Поднимите `version.json` и `CHANGELOG.md`, закоммитьте, поставьте тег
   `v<version>` и запушьте его.
2. Создайте на GitHub релиз с этим тегом и текстом изменений.
3. Соберите и загрузите оба файла:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\publish-release.ps1 -Version 0.6.1
```

`publish-release.ps1` сам вызывает `build-release.ps1`, проверяет, что
`version.json` совпадает с версией, находит релиз по тегу, заменяет старые
одноимённые assets и в конце проверяет, что оба файла на месте. Токен берётся
из `GITHUB_TOKEN`/`GH_TOKEN` или из git credential manager.

Автоматический вариант — `.github/workflows/release-assets.yml`: при
публикации релиза GitHub Actions собирает архив и SHA и прикладывает их к
релизу. Если Actions в репозитории выключены, используйте
`publish-release.ps1` вручную.

В архив входят `index.html`, `index.py`, `manifest.json`, `version.json`,
иконки, `assets`, `cgi-bin`, `service`, `init.d`, `lighttpd`, `deploy` и
`bin` (`yt-dlp`, если есть). `__pycache__`, `tests`, `src` и `.git` в архив не
попадают: `src/` нужен только для сборки `index.html` на компьютере, на
колонке он не используется.

### Каналы: стабильный и бета

Канал выбирается в карточке «Обновление» и хранится в
`/data/mypult/update.json`. На стабильном канале prerelease-релизы
игнорируются, на бете — видны.

- **Бета-релиз**: тот же порядок, но при создании релиза поставьте галочку
  **Set as a pre-release**. `version.json` и тег при этом обычные (`0.6.98`,
  `v0.6.98`) — бета помечается флагом релиза, а не суффиксом версии.
- **Возврат на стабильную**: установка беты запоминается
  (`installed_prerelease`), и при переключении на стабильный канал панель
  предлагает вернуться на стабильную версию, даже если она младше беты.
  Это предложение показывается только в карточке, без всплывающего окна;
  кнопка называется «Вернуться на стабильную».
- **Откат**: кнопка «Откатить обновление» восстанавливает последнюю
  резервную копию (`/data/mypult-update-backup-*`) и перезапускает панель.

## Скриншоты для README

Сделайте свои на тестовой сети без реальных данных: подписка VPN и SSID
должны быть фиктивными, IP — из диапазона `192.168.1.x`. Не показывайте
карточку «Нейросеть» с ключом и «Резервная копия» с реальными настройками.
